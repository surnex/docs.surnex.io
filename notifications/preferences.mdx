**Settings → Channels** lists the places a notification can arrive. Channels belong to the **organization**, not to you: switching one off switches it off for every member.

## Channels

| Channel | Default | Setup |
| --- | --- | --- |
| **In-app** | Always on | None — delivers to the [Notification center](/notifications/view) |
| **Email** | **On** | None — sent to every member's sign-in address |
| **Slack** | Off | An incoming webhook URL (`https://hooks.slack.com/services/…`) |
| **Discord** | Off | An incoming webhook URL (`https://discord.com/api/webhooks/…`) |

**Email is on for every organization until an owner or admin turns it off.** In-app has no switch — it's the record the Notification center reads from.

Slack and Discord are opt-in. Click **Set up** on the channel and paste the channel's own incoming webhook. The URL must use HTTPS and be Slack's or Discord's webhook address exactly; anything else — another host, a proxy, a port — is refused. **Disconnect** turns the channel off and deletes the stored webhook, so reconnecting means pasting a new one.

A webhook URL is the credential that posts into your channel, so members see only its host (`https://hooks.slack.com/…`). Owners and admins see the full URL.

### Scheduled reports

[Automated reports](/reports/automation) are always emailed to the recipients the automation names, even with the Email channel switched off. The Email switch covers Surnex's own notifications, not a delivery you've set up on purpose.

## Events

Every event is on by default for every channel that's on. Each can be turned off individually per channel with the API's `PUT /v1/organizations/{orgId}/notifications/rules`.

### Ranking

| Event | Fires when |
| --- | --- |
| **Rank Improved** (`rank_improved`) | A keyword improved by 5+ positions |
| **Rank Dropped** (`rank_dropped`) | A keyword dropped by 5+ positions |
| **Entered Top 3** (`entered_top3`) | A keyword entered positions 1–3 |
| **Entered Top 10** (`entered_top10`) | A keyword entered positions 1–10 |
| **Lost Top 10** (`lost_top10`) | A keyword fell out of the top 10 |
| **Lost Top 100** (`lost_top100`) | A keyword stopped ranking |

These match the [ranking alerts](/tracking/alerts) exactly — the thresholds are the same. A rank check sends one notification per alert type it raised, so turning off **Rank Improved** silences only improvements. The alerts themselves are always generated and always appear in the feed.

### Audits

**Audit Complete** — a site audit finished processing.

### Backlinks

| Event | Fires when |
| --- | --- |
| **Backlinks Dropped** (`lost_backlinks`) | Total backlinks fell by 20% or more |
| **Referring Domains Dropped** (`referring_domains_dropped`) | Referring domains fell by 10% or more |
| **Referring Domains Spike** (`referring_domains_spike`) | Referring domains rose by 50% or more — flagged as potential spam |
| **Domain Rank Dropped** (`domain_rank_dropped`) | Domain rank fell by 50+ points |

Each change is its own notification, so each event can be turned off without losing the others.

**Referring Domains Spike** is the one worth keeping even if you turn off the rest. A sudden 50% jump in referring domains is more often a negative-SEO or spam-link event than a marketing success, and it's the kind of thing you want to hear about immediately.

### AI Visibility, Local SEO, Web Vitals

- **Snapshot Complete** — an AI visibility snapshot finished
- **Rankings Check Complete** — a [local SEO](/local/overview) check finished, with how many keywords were checked, how many grid points found you, and the share in the top 3
- **Vitals Check Complete** — a Core Web Vitals audit finished

### Reports

**Scheduled Report Ready** — an [automated report](/reports/automation) has been generated.

## Choosing what to keep

The completion events — audit, snapshot, local, vitals — fire every time a job finishes. On a project checking daily, that's a notification a day per feature. With email on by default, those are the first to turn off for email if the inbox gets noisy.

The events genuinely worth pushing to email or Slack are the ones you'd act on: **Lost Top 10**, **Lost Top 100**, **Referring Domains Spike** and **Domain Rank Dropped**. Everything else reads fine in the [Notification center](/notifications/view) when you next look.

## Permissions

Changing channels and event rules requires the **owner** or **admin** role. Members can view the channels — with webhook URLs masked — and read notifications. See [Roles and permissions](/organizations/roles).

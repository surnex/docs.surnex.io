**Notifications** — "Stay up to date with ranking changes, audit results, backlinks, and usage alerts" — is the in-app feed for everything Surnex wants to tell you.

## Tabs

| Tab | Shows |
| --- | --- |
| **Unread** | Notifications you haven't opened |
| **Ranking** | Position changes and threshold crossings |
| **Audits** | Audit completions |
| **Backlinks** | New and lost links, referring domain movement, domain rank changes |

## Actions

- **Mark as read** — opening a notification marks it read
- **Delete** — remove one, confirmed with *"Are you sure you want to delete this notification? This action cannot be undone."*
- **Clear all read** — *"This will permanently delete all notifications you've already read."*

**Clear all read** is the practical way to keep the feed usable. Completion notifications accumulate quickly on a project checking daily.

## Empty states

| Tab state | Message |
| --- | --- |
| No unread | **You're all caught up** |
| Nothing at all | **No notifications yet** |

## What appears here

Everything you've enabled for the **In-App** channel in [notification preferences](/notifications/preferences): ranking alerts, audit and check completions, backlink movement, report readiness, and usage warnings.

Notifications are per member. Clearing yours doesn't affect a teammate's.

## Notifications vs. the ranking alert feed

They overlap, and it's worth knowing which to use:

|  | Notification center | [Position changes](/tracking/changes) |
| --- | --- | --- |
| Scope | Everything across the project | Ranking alerts only |
| Grouping | By category tab | By date, with type filters |
| Extra views | — | Biggest Movers over a chosen date range |

Use the notification center as an inbox — has anything happened I should know about? Use [Position changes](/tracking/changes) when you're specifically investigating ranking movement, because it groups by date and lets you compare arbitrary ranges.

## Not seeing something

If an event you expected isn't here, check three things in order:

1. **Is the In-App channel enabled for that event** in [preferences](/notifications/preferences)?
2. **Did the underlying job run?** A completion notification only fires when the job completes — see [How data collection works](/projects/data-collection).
3. **Did the event actually meet its threshold?** Ranking alerts need a 5+ position move or a band crossing. See [Ranking alerts](/tracking/alerts).

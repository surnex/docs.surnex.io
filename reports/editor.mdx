The editor is where a report is built. Open a report from the [Reports](/reports/list) list.

## Widgets

Content is added as widgets on a grid. Click to open the **Add widget** panel, choose one, and it's placed on the canvas.

### Widget types

Every widget renders as one of six visual forms:

| Type | Best for |
| --- | --- |
| **Stat Card** | A single headline number |
| **Line Chart** | A metric over time |
| **Bar Chart** | Comparing categories |
| **Donut Chart** | Composition of a whole |
| **Table** | Row-level detail |
| **Text / Note** | Commentary, headings, context |

### Presets

Rather than building each widget from scratch, the panel offers presets that already know which metric to pull. They cover the whole platform:

**Rankings** — Ranking Overview, Ranking Changes, Ranking History, Total Keywords, Avg. Position, Top 3 Keywords, Top 10 Keywords, Visibility Score, Position Distribution, the individual position bands (1–3, 4–10, 11–20, 21–50, 51–100, Not Ranking), Improved, Declined, New in Top 100, Lost from Top 100, Top Gainers, Top Losers, All Keywords

**Backlinks** — Backlink Summary, Backlink History, Anchor Texts, Total Backlinks, Referring Domains, Domain Rating

**Audits** — Audit Summary, Audit Issues, Audit Pages

**AI and GEO** — GEO Overview, GEO Trend, GEO Prompts

**Other** — Web Vitals, Local SEO Overview, Domain Overview

The Local SEO metrics include **Map Top 3 Coverage** — the share of your [local grids](/local/keywords) where you're in the top 3 — and **Avg. Map Position**, alongside the counts of keywords in the local top 3 and top 10.

Picking a preset creates the widget with a sensible default visual type, which you can then change.

### Text widgets

**Text / Note** is the widget most often skipped and most worth using. A report of charts without commentary makes the reader do the interpretation — which, for a client report, is the part you're being paid for. Put a short summary at the top and a note under any chart that needs explaining.

## Configuring a widget

Select a widget to open its configuration panel, where you set its type and options. Changes preview live against real project data.

## Layout

Widgets are moved and resized on the grid. Arrange top-down in the order you want the story read: headline numbers first, then trends, then detail tables.

Keep in mind the report will be read as a [PDF](/reports/share) as often as in the browser. Wide tables and dense charts survive that transition poorly; a few well-chosen widgets read better than a comprehensive dashboard.

## Date range

The editor has a date range that applies to the whole report. Every widget reads its data for that range:

- **A figure** — average position, referring domains, health score — is its value **on the last day of the range**, or the last day before it with data. A September report shows the figures as they stood on 30 September, however late you open it.
- **The change** beside a figure compares that value with the last one **before the range started** — this period against the one before. For a position, a fall is shown green: moving from 14 to 12 is an improvement.
- **A line chart** has a point for each day in the range with data.
- **A table** shows the list as it stood on the last day of the range: all keywords, top gainers and losers, AI Overview keywords, AI visibility prompts and cited sources, the backlink comparison, the audit's issues and pages, and web vitals opportunities. The exception is the **top anchors** table: Surnex keeps only the latest backlink profile, so it always shows the current anchors.

This is what makes a report reusable: duplicate last month's report, move the range forward, and every widget re-reads. It's also what to check first when a report shows unexpected figures — a range that hasn't been advanced is the usual cause.

## Live data

Widgets read from the project when the report is viewed, from stored data. A range that has ended shows the same figures whenever it's opened; a range that includes today fills in as new checks land.

A widget for a feature that hasn't been collected shows nothing. An audit widget shows the latest crawl that finished by the end of the range — on a project whose last crawl was months ago, that old crawl. See [How data collection works](/projects/data-collection).

The same figures are available to other reporting tools, such as Oviond, through the [reporting API](/api/reporting).

---
title: "How data collection works"
description: "Which data is collected on a schedule, which runs on demand, and which is fetched live."
---

Almost nothing in Surnex is fetched when you open a page. Data is collected in the background, written to your project, and read back when you visit. This is why a page can show yesterday's figures and why a fresh project looks empty at first.

Understanding which mode a feature uses tells you what to expect when a number looks stale.

## The three modes

### Scheduled

Four job types have a schedule, and every project gets all four:

| Job | Feature |
| --- | --- |
| `rank_check` | [Rank tracking](/tracking/overview) |
| `backlink_snapshot` | [Backlinks](/backlinks/overview) |
| `geo_snapshot` | [GEO visibility](/geo/overview) |
| `local_ranking_check` | [Local SEO](/local/overview) |

A new project gets all four enabled at **00:00 UTC** — daily, except GEO visibility and Local SEO, which are weekly: each GEO check asks six AI engines per prompt, and each Local SEO check searches every keyword from every point of its [grid](/local/locations). Report delivery is scheduled separately, per report — see [Automate delivery](/reports/automation).

Each schedule has three parts:

| Part | Meaning |
| --- | --- |
| **Cadence** | How often — daily, every 3 days, weekly, biweekly, or monthly |
| **Run hour** | Which hour of the day, in the schedule's own timezone. Can be unset |
| **Timezone** | Any IANA timezone, and it **is** applied |

Cadence is a real interval — three days means three days, everywhere in the year. It isn't a day-of-week or day-of-month rule, so "weekly" is seven days from the last run rather than a fixed weekday.

Leaving the **run hour** unset makes the cadence pure elapsed time: the job runs every N hours from whenever it last ran, with no calendar involved.

The scheduler wakes every minute and claims whatever is due. Claiming a schedule advances its next run in the same statement, so a job can't be picked up twice — there's no dedup window to reason about and no "did this already run recently" guard.

### Collected on demand

These have no schedule. They run when you ask:

- [Site audits](/audits/run) — start a crawl from the Audits page
- [Web vitals](/web-vitals/overview)
- [AI search](/ai/overview) — AI Mode, ChatGPT visibility, benchmarking, citation gap
- [Domain overview](/domains/overview) and [tech stack](/domains/tech-stack)
- [Keyword research](/keywords/research)

<Note>
  Creating a project **starts its first collection straight away**: rankings, backlinks and GEO, the full backlink profile, a site audit, a web vitals check, domain overview, tech stack, keyword research, and one LLM benchmark. Local SEO's first check runs when you add keywords at a [location](/local/locations). Rankings arrive within minutes; the rest appear as each job finishes. See [Create a project](/projects/add#what-happens-next).

  After that first run, audits and web vitals never run on their own. A months-old audit score means nobody has crawled since.
</Note>

### Live

Two pages call out while you wait, with no stored history:

- [Explore trends](/trends/explore)
- [Trending now](/trends/trending)

These are the only pages where refreshing gives you newer numbers.

## Why a page is empty

| Cause | What you'll see | What to do |
| --- | --- | --- |
| The first run is still going | Empty state on a new project | Wait — each page fills as its job finishes |
| It's an on-demand feature | Empty audits, web vitals, domain data | Run it |
| Nothing to collect | No backlinks on a new domain, no Maps results for a keyword | Nothing — the job succeeded and found nothing |
| The job failed | Data for other features but not this one | Check your [Inbox](/notifications/view) |

## One job at a time

The most expensive jobs refuse to start if one is already running for that project. Requesting a second [site audit](/audits/run) while the first is in flight is rejected rather than queued — a crawl is the slowest and costliest thing the platform does, and the slowest to notice you've started twice.

## Usage

Scheduled collection doesn't spend your monthly allowances. It's what the held allowances pay for: a daily rank check on 400 keywords is covered by holding 400 tracked keywords, whatever the cadence. GEO snapshots are covered by your AI prompts, and local checks by your local locations.

On-demand work is what spends: audits spend site audit pages, AI search runs spend AI brand audits, and research spends research lookups. A new project's first run counts as on-demand work — about five research lookups, one AI brand audit, and up to 101 site audit pages.

If the organization holds more than its plan allows — after a downgrade, say — scheduled checks cover the oldest rows up to the limit, across the whole organization. When a trial or subscription ends, scheduled runs stop, and runs skipped while there was no plan aren't made up afterwards.

[Usage and limits](/billing/usage) shows what's been used; [Plans](/billing/plans) lists the allowance on each plan.
